# Product

## Platform

web

## Stack

React, Vite, strict TypeScript, pnpm, SQLite/Drizzle and local Node API. These choices come from ARCHITECTURE.md. Build directly from code for this iteration under the user's instruction to keep proceeding; no standing image/code workflow preference is inferred.

## Users

Individual developers switching between side projects and coding agents, often returning after weeks away (PRD.md).

## Product Purpose

Show where a project stopped, what is supported by current evidence, and the next useful action. The project owns continuity across agents.

## Operating Context

Local repositories, Git, evidence-backed checkpoints, optional historical conversations and optional authenticated analyzer. User requested dashboard with mock data first, followed by real tooling and gradual project onboarding/testing.

## Capabilities and Constraints

Default local-only storage, loopback network, no telemetry or mandatory API key. Keep sample data visibly separate from real project evidence. No generated completion percentages. Existing CLI deterministic continuity is fixture-tested; full V1 is still being built.

## Evidence on Hand

PRD, architecture and imported specifications; CLI source and disposable Git fixtures. No real user projects have been registered for dashboard verification yet. Demo projects and activity must be labeled sample.

## Product Principles

Evidence before interpretation. Current Git and semantic freshness are distinct. Agents are interchangeable. Failed analysis preserves useful factual state.

## Open decisions

Resume-first with portfolio and timeline alongside is confirmed by the user. No pre-existing brand, visual assets or dashboard identity was supplied. Keyboard operation, readable contrast and responsive layouts are implementation quality requirements.
